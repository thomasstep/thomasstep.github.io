March brought some new learning for me. I started off with someone I’ve been familiar with for a while but never experimented with personally: chaos engineering. AWS has a service called Fault Injection Service (FIS) that I read up on and produced a CloudFormation template for a project. It was extremely easy to get going, considering the capabilities that it provides.

My other big learning moment was Claude Code. My company provided about 9 hours of training for developers that I joined. I was impressed with the demos despite normally being a critic. The use cases that were shown off looked relevant, and Claude seemed to produce real working code. Before this, I had only used Copilot and had mixed results. Later on in the month, I used Claude to create a CLI for a new project I’m working on now that involves configuration management. Before, we had to make manual changes in our AWS environment to get things correctly configured. I turned that into a JSON format, stored it in our Git repo, and created a CLI to push, pull, and diff that configuration. Well…I told Claude to do it at least. At first, I was impressed until I tried running it for the first time and the CLI told me it was going to delete a bunch of configuration out of AWS. I ended up going through all the code manually and refactoring bits and pieces.

The whole generative AI thing seems like fun. I get why developers have flocked to it. Whenever Claude is cooking up some code, I get a dopamine hit, and that dopamine hit has got to be what gets people hooked on it. The quality of the code is not great, though. Not bad, but not great. As I said, I feel like I needed to hand-hold the code through to completion. It was as if an intern wrote it. I do wonder how reading comprehension and critical thinking skills will change (probably for the worse) over the years of AI adoption. Instead of diving into technical documentation or coming up with a clever way to structure code, I can just ask Claude to copy and paste something that it’s read online.

Another couple of small learnings were Better Auth and shadcn. Better Auth is a prebuilt authentication solution. It comes with a server and helpers for the front end. I spun up a Lambda to function as the server and a Next.js app to function as the front end. It was surprisingly easy, and the things I have seen online make it seem like a reliable and scalable solution. I guess I will be leaving my old Crow Auth project in the dust. Shadcn is a component library made by someone at Vercel. Nothing special or anything, just nice to look at. It’s all Tailwind behind the scenes, which makes it easy to tweak if you want.

At the beginning of this month, I changed roles, so I am now a team lead. So far, the biggest change is just the number of meetings. I have been involved in architecture meetings and customer meetings, which is not surprising to me. I am excited for the change in my position and project.
